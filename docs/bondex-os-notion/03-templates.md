# 03. ページテンプレート仕様

各DBに「新規」ボタンで呼び出せるページテンプレートを用意します。
Notionでの作り方: DB右上の `New ▾` → `+ New template` → 下記の本文とプロパティ初期値を設定。

---

## ① DMC テンプレート — `新規DMC`

**プロパティ初期値**: 営業ステータス=`未着手` / 優先順位=`B` / 国=`日本`

**本文**:
```
## 会社概要
（事業内容 / 規模 / 取扱商流 / 得意分野）

## なぜBondEx候補か
- 需要の束（団体/FIT/添乗員同行）:
- 地域適合（北海道等）:

## 接触履歴
（Meetingsリレーションに集約。ここには要点のみ）

## 次の一手
- [ ]

## 出典 / 一次情報
- URL:
- 取得日:
```

---

## ② Meetings テンプレート — `商談メモ`

**プロパティ初期値**: PoC化可能性=`中` / 要約ステータス=`未要約`

**本文**:
```
## アジェンダ
-

## 議事（時系列）
-

## 決定事項
-

## 課題 / 論点
-

## 宿題（担当・期日）
- [ ] （BondEx）
- [ ] （先方）

## Next Action
- [ ]
```

> Fathom URL を入れておくと、Claude Codeが文字起こしを取得して議事録・宿題・Next Actionを自動下書きできる（[05参照](./05-ai-automation.md)）。

---

## ③ Travelers テンプレート — `旅行レコード`

**プロパティ初期値**: トラブル有無=`なし` / 添乗員=OFF

**本文**:
```
## 行程サマリ
（日程 / 主要観光地 / 宿泊）

## 荷物・配送
- 発地 → 着地:
- 特記（大型・冷蔵・破損注意など）:

## 振り返り（分析メモ）
- 需要のヒント:
```

> 数値（人数/配送件数/重量/金額）は必ずプロパティに入れる。本文に書くと集計できない。

---

## ④ Stakeholders テンプレート — `関係者`

**プロパティ初期値**: ステータス=`未接触` / 優先度=`B`

**本文**:
```
## 概要 / 役割
（BondExにとっての位置づけ）

## 連携ポイント
- 提供してもらえるもの:
- こちらが提供するもの:

## 接触履歴
（Meetingsに集約）
```

---

## ⑤ Documents テンプレート — `文書`

**プロパティ初期値**: ステータス=`ドラフト` / 生成元=`人手` / 版=`v0.1`

**本文**:
```
## 目的
## 想定読者
## 要点
## 変更履歴
- v0.1 初版（日付 / 作成者）
```

---

## ⑥ PoC テンプレート — `PoC計画`

**プロパティ初期値**: ステータス=`構想`

**本文**:
```
## 目的 / 仮説
（このPoCで検証すること）

## 成功基準（KPI）
- 目標配送件数:
- 目標売上:
- 目標参加人数:
- 利用率目標:

## 体制
- ランドオペ:
- ホテル / 空港:
- 物流:

## スケジュール
| フェーズ | 期間 | 担当 |
|---|---|---|

## リスク / 対策
-

## 結果（実施後に追記）
- 実績 vs 目標:
- 学び:
- 次アクション:
```

---

## ⑦ Decision Log テンプレート — `意思決定`

**プロパティ初期値**: ステータス=`有効` / 日付=今日

**本文**:
```
## 背景
（なぜ今この判断が必要か）

## 選択肢
1. 案A —
2. 案B —
3. 案C —

## 評価軸
- コスト / スピード / 拡張性 / リスク

## 採用理由
（なぜこの案か。捨てた案を選ばなかった理由も）

## 決定内容
（何を決めたか。具体的なアクション）

## 見直し条件
- 次回見直し日:
- 前提が崩れる条件:

## 結果（後日追記）
-
```
