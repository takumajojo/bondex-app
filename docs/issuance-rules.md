# 発行(バウチャー / 送り状)の運用ルール

確定日: 2026-08-27(谷口さん承認)

BondEx が扱う「発行」には**2種類**あり、印刷できるタイミングが異なる。混同しやすいので明文化する。

---

## 1. バウチャー(BondEx が発行する書類)

- **キャリア非依存**。予約確定時に**即発行**でき、**発送日の30日以上前でもいつでも印刷・共有できる**。
- ホテル/旅行者に早めに渡したい書類は、このバウチャーで対応する。

## 2. 送り状(佐川 / ヤマトの配送伝票・Ship&co 経由)

- **配送会社のハード制約により、発送日の「30日前」からしか発行できない。**
  - 佐川: `E1-0046「発送日が30日を超える未来日付です」`
  - ヤマト: `ES003001「出荷予定日は送り状発行日から30日以内」`
- **30日以上前の送り状印刷は物理的に不可能**(どのキャリアでも)。無理に発行を試みない(エラー回避)。
- 実装上のリードタイム上限は両社とも `maxLeadDays = 30`(`lib/carrier.ts`)。

---

## 3. 自動発行ルール(送り状)

- 各区間が**発送30日前**に入ったら、**送り状を自動発行**する(1区間につき1回のみ)。
- 発行に成功したら:
  - 書類一式(バウチャー+送り状)を **Google Drive の予約番号フォルダへ自動格納**。
  - 「**送り状を発行しました / Drive に格納しました**」の通知メールを送る。
- 再発行しても Ship&co は既存ラベルを返すだけ(`shipandco/create` の idempotency)= **二重課金しない**。

## 4. 多区間(1予約に複数区間)のルール

- 30日以内の区間 → **発行**。
- 30日を超える区間 → **自動保留(発行窓外)**。30日前になったら自動発行。
- 窓外の区間があっても、**窓内の区間だけは正常に発行される**(窓外区間のエラーで窓内を巻き込まない)。

## 5. やらないこと

- 30日を超える送り状を**強制発行しようとしない**(Ship&co が必ず弾くため)。
- 発行を無限に繰り返さない(1回発行=以後は既存ラベル参照)。

---

## 実装状況 / 根拠

- 佐川リードタイム 30日: `lib/carrier.ts`(`sagawa.maxLeadDays = 30`)。
- 発行窓外の deferred 化: `app/api/shipandco/create/route.ts`(`gap > carrier.maxLeadDays` で deferred)。
- 発行リマインド(現状): `app/api/cron/issue-due/route.ts`(**自動発行はまだ未実装 → リマインドのみ**)。
- **未実装(バックログ)**: 「30日前 自動発行 + 発行しましたメール + Drive自動格納」(本ルール §3)。
